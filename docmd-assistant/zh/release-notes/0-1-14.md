`docmd-assistant` v0.1.14 引入了通用的、与模型提供商无关的工具解析器，能够在所有主流大模型和输出格式中可靠地拦截并执行 AI 工具调用。

## 主要特性与增强

### 通用多格式工具调用解析器（修复 docmd [#206](https://github.com/docmd-io/docmd/issues/206)）

- **平衡 JSON 扫描器**：无论键名顺序如何（`{"name": ..., "parameters": ...}` 或 `{"parameters": ..., "name": ...}`）、嵌套层级或字符串编码参数，均能可靠提取内联 JSON 工具对象。
- **Markdown 代码块解析**：精准检测并提取标准 Markdown 代码块（````json ... ````、````tool_call ... ````）中的工具负载。
- **括号工具调用语法**：全面支持带有标签与括号的工具表达格式，包括：
  - `[Tool Call: search_documentation({"query":"..."})]`
  - `[Tool Call: get_site_structure()]`
  - `[TOOL_CALL: search_documentation(...)]`
  - `[Function Call: name(...)]`
- **零参数与函数式语法**：支持零参数工具调用（`get_site_structure()`）及函数式参数列表（`tool_name(query="value")`）。

### 已注册工具动态匹配

- **注册表直连匹配**：助手引擎的执行循环现在将所有已注册工具名称（`search_documentation`、`get_site_structure` 及自定义工具）直接传递给 `parseAssistantOutput` 进行确定性识别。

### 零底层工具字符串泄露

- **纯净用户聊天体验**：彻底防止未解析的工具调用标记直接显示给聊天用户；所有工具调用均在后台自主执行并合成为自然流畅的解答。

## 已解决的问题

- **[docmd #206](https://github.com/docmd-io/docmd/issues/206)**：AI 聊天返回工具调用原始字符串而非真实回答（由 [@mewc](https://github.com/mewc) 反馈）。
