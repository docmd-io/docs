# 变量与动态运行时

docmd 提供了全新的**变量与个性化引擎**，将静态构建期插值与客户端响应式个性化完美结合。

无需在数十个 Markdown 文件中硬编码公司名称、API 地址、发布年份或版本号，您可以直接使用简洁的模板表达式引用动态变量。

```markdown
欢迎阅读 **{{ site.title }}** v{{ docmd.version }} 文档！
当前版权所有：© {{ docmd.buildYear }}。
```

## 模板语法

变量引擎使用双大括号语法：

```markdown
{{ variableName }}
```

### 回退默认值（Fallback）

如果某个变量可能未定义，可使用 `||` 运算符指定默认回退值：

```markdown
连接到我们的服务器：`{{ server.endpoint || "https://api.example.com" }}`。
欢迎回来，{{ user.name || '访客' }}！
专为版本 {{ targetVersion || 2.0 }} 构建。
```

回退值支持：
* 单引号字符串：`'示例'`
* 双引号字符串：`"示例"`
* 数字：`42` 或 `2.0`
* 标识符：`default`

### 空格容错

表达式支持在变量名称和运算符两侧包含空格：

```markdown
{{   myVar   }}
{{ env.PORT || "8080" }}
```

## 变量生命周期：构建期 vs 运行时

docmd 将变量生命周期清晰地划分为两个阶段：

```
┌────────────────────────────────────────────────────────────────────────┐
│                             构建期解析                                 │
│  - 内置动态变量（docmd.version, docmd.buildYear, Git 信息）            │
│  - 系统环境变量（env.NAME, DOCMD_VAR_*）                               │
│  - docmd.config.json 变量（静态字符串，配置字段）                      │
│  - 在 docmd build 执行时直接渲染为最终静态 HTML                         │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                            客户端运行时                                │
│  - 由 docmd-runtime.js (window.docmd) 驱动                             │
│  - 实时水合动态标记（<span data-docmd-var="...">）                     │
│  - 交互式个性化：实时 API 密钥、用户会话                               │
│  - 跨窗口 postMessage 通信与事件派发                                   │
└────────────────────────────────────────────────────────────────────────┘
```

### 静态构建期变量

在 `docmd build` 期间解析的变量会直接编译到静态 HTML 中，无需任何客户端 JavaScript 开销，亦不会产生页面布局偏移。

### 响应式动态变量

标记为动态或包含用户会话属性（如 `user.name` 或 `user.apiKey`）的变量会被包装在响应式 DOM 标记中：

```html
<span data-docmd-var="user.name" class="docmd-var">访客</span>
```

在运行时，`docmd-runtime.js` 会自动填充并在整个页面、代码块以及单页应用（SPA）无刷新路由跳转中保持这些值的同步更新。

## 架构：引擎与界面的清晰分离

为了保证极速的性能与稳定性，docmd 在界面展示与无头（Headless）运行时之间保持了严格的界限：

* **`docmd-runtime.js`**：引入到所有模板（包括默认模板和 `summer` 等自定义主题）中的无头运行时引擎。它负责变量注册表、订阅管理、本地存储与跨窗口通信，绝不干扰界面动画或样式。
* **`docmd-main.js`**：负责主题切换、移动端导航、SPA 页面路由及 DOM 交互的视觉展示脚本。在每次 SPA 路由切换时，它会自动调用 `window.docmd.sync()`，确保动态变量瞬间完成注水渲染。
