### Highlights

`docmd` v0.9.9 introduces a comprehensive **Variables & Personalisation Engine** spanning static build-time template interpolation and dynamic client-side reactivity, resolves search index loading across versioned directory mounts, hardens template layout slot resolution and monorepo peer dependency isolation, improves Single-Page Application (SPA) logo navigation routing, and incorporates automated context synthesis optimisations for the AI assistant plugin.

- **Unified Variables & Personalisation Engine (`@docmd/core`, `@docmd/parser`, `@docmd/ui`)**: Enables clean `{{ variable }}` interpolation across documentation files, site banners, and footer copyright strings. Provides zero-configuration built-in variables (`docmd.version`, `docmd.buildYear`, `docmd.gitCommit`, `docmd.gitBranch`, `page.slug`, `page.title`), configuration variable trees with fallback defaults (`{{ var || 'default' }}`), and syntax escaping via `\{{ ... }}`.
- **Interactive Playground Plugin (`@docmd/plugin-playground`)**: Core plugin bundled by default with zero configuration. Brings self-runnable JavaScript sandboxes, active codebase script sourcing (`::: playground src="..." /:::`), interactive Live and Code view tab switching (`tabs`, `tabs:code`), live HTML/CSS previews, real-time console interception, graceful warning alerts for missing scripts, and direct `docmd-runtime` integration (`docmd.var.get()`, `docmd.var.set()`) with zero extra assets loaded when unused.
- **Universal Headless Client Runtime (`@docmd/ui`)**: Ships `docmd-runtime.js` across all layout templates (`default`, `summer`). Exposes `window.docmd` with reactive DOM rehydration (`<span data-docmd-var="...">`), live code snippet updates for personalized API keys, and cross-frame `postMessage` synchronisation for embedded developer portals.
- **Versioned Search Path Resolution (`@docmd/plugin-search`)**: Fixed search index loading on sites mounted under versioned base paths like `/vX.Y.Z/` (PR #266 by @Goldloli, closing #262). Prefers the authoritative build-time `window.DOCMD_SITE_ROOT` to prevent version segment stripping on mono-version deployments.
- **SPA Logo Routing & Navigation Fixes (`@docmd/ui`)**: Hardened logo link handling so custom external URLs (e.g. corporate homepages) and root-relative workspace links navigate seamlessly without unwanted client-side SPA routing intercepts.
- **Template Layout Slot Resolution & Dependency Hardening (`@docmd/api`, `@docmd/ui`)**: Eliminated false-positive layout slot warnings for themes like `summer`. Gated monorepo source detection within pre-flight runtime dependency checks and isolated peer dependency installs to prevent package pruning in npm v7+ workspaces.
- **AI Assistant Context & Tool Optimisations (`@docmd/plugin-ai`)**: Streamlined documentation tool calling with Snippet-First Synthesis, ensuring AI responses deliver precise documentation passages and code examples with minimal roundtrips.
- **Dependency Maintenance & Upgrades**: Updated npm dependency group across workspace packages (PR #265) and bumped `docker/login-action` (PR #264).

### Unified Variables & Dynamic Personalisation Engine (`@docmd/core`, `@docmd/parser`, `@docmd/ui`)

v0.9.9 introduces a first-class Variables Engine that addresses documentation maintenance at both compile-time and run-time:

- **Build-Time Static Interpolation**: Replaces `{{ variable }}` tokens directly during static site generation with zero client-side JavaScript overhead. Supports fallback values using the `||` operator (e.g. `{{ env.PORT || "8080" }}`) and literal syntax escaping with `\{{ ... }}`.
- **Built-in System & Repository Variables**:
  - `docmd.version` (`DOCMD_VERSION`): The active compiler release version.
  - `docmd.buildYear` (`BUILD_YEAR`): 4-digit calendar year of the build.
  - `docmd.buildDate` / `docmd.buildTime`: ISO 8601 build timestamps.
  - `docmd.gitCommit` / `docmd.gitBranch`: Git SHA and branch metadata extracted dynamically via repository discovery.
  - `site.title` / `site.base`: Global workspace configuration properties.
  - `page.title` / `page.slug` / `page.path`: Document context properties.
- **Pre-Render Configuration Interpolation**: Evaluates variables inside `docmd.config.json` before template compilation. Authors can define dynamic top banners (`"content": "**docmd v{{ docmd.version }} is live!**"`) and automated footer copyright strings (`"copyright": "© {{ docmd.buildYear }} Acme Corp"`).
- **Environment Variable Promotion**: System environment variables are accessible via `{{ env.VARIABLE }}`. Any variable prefixed with `DOCMD_VAR_` is automatically promoted to top-level for clean template authoring.
- **Headless Client Runtime (`docmd-runtime.js`)**: Bundled across all themes. Dynamic variables declared under `variables.dynamic` or prefixed with `user.` are rendered as `<span data-docmd-var="...">` markers. The runtime provides `window.docmd.var.set()`, `get()`, `list()`, and `sync()`, enabling instant personalization of API keys in code snippets without full-page reloads.

### Interactive Playground Plugin (`@docmd/plugin-playground`)

v0.9.9 introduces `@docmd/plugin-playground`, a lightweight code runner and live component sandbox enabled by default as a core plugin:

- **Zero-Config Live Execution**: Add `playground` or `live` to any fenced code block (` ```js playground `) or use the `::: playground` container to enable in-page code execution.
- **Continuous Codebase Sync via `src`**: Link local scripts directly via `::: playground src="./counter.js" /:::`. Scripts are resolved and safely inlined at compile time, eliminating stale copy-pasted documentation snippets.
- **Live & Code View Tab Switching (`tabs`, `tabs:code`)**: Easily toggle between interactive live component preview and underlying source code with dedicated header tabs.
- **Graceful Warning & Error Handling**: Missing script paths emit non-breaking warning banners with fallback code without aborting builds; runtime errors render structured execution alerts.
- **Real-Time Console Interception**: Formatted logging for `console.log`, `info`, `warn`, and `error`, plus evaluation return values.
- **Isolated HTML & CSS Component Preview**: Sandboxed preview panel for rendering interactive UI widgets.
- **Client Runtime Integration**: Seamless interoperability with `window.docmd` and the Variables Engine (`docmd.var.get()`, `docmd.var.set()`, `docmd.theme.toggle()`).
- **Zero Asset Overhead**: Employs conditional asset injection so documentation pages without playground blocks load zero extra CSS or JavaScript.

### Search Index Resolution for Versioned & Sub-site Mounts (`@docmd/plugin-search`)

Contributed by @Goldloli in PR #266 (closing issue #262):

- On sites whose configured base path itself ends in a version segment (e.g. `/docs/v1.2.3/`), the previous relative path deduction stripped the trailing version segment, causing the search plugin to request `_docmd-search/` from the parent directory.
- The client now prioritises the build-time absolute `window.DOCMD_SITE_ROOT` injected by `layout.ejs`. Relative deduction is retained as a robust fallback for legacy templates and standalone search pages.

### SPA Logo Routing & Navigation Fixes (`@docmd/ui`)

- Resolved an issue where clicking the site logo with an external destination (e.g. `https://docmd.io`) was intercepted by the SPA client router, resulting in an in-page navigation error.
- Verified that external links, anchor targets, and cross-origin links properly bypass SPA interceptors while internal workspace transitions remain instant and smooth.

### Template Resolution & Monorepo Runtime Dependency Hardening (`@docmd/api`, `@docmd/ui`)

- Resolved the `[ WARN ] Template "summer" declared slot "layout" but file not found` warning observed in multi-project local development.
- Gated monorepo source package resolution in `runtime-deps.ts` to execute only when `isMonorepoContext` is valid, preventing pre-flight batch installation from skipping necessary template packages.
- Added hierarchical node module resolution fallbacks in `@docmd/ui` and `@docmd/plugin-search` to prevent npm v7+ from pruning sibling dependencies during sub-project development.
